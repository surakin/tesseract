# Sample world assets

Test assets for the experimental 3D call room: a meadow scene and a robot avatar whose face is a screen. Both files are generated by
`generate_assets.py` from primitives and seeded random numbers, with no third-party models or textures.

| File | What it is |
|---|---|
| `green_field.glb` | A flat 160 m square of solid grass with a clearing in the middle, 36 trees scattered across the meadow and a ring of 280 trees from 44 m to 68 m out. |
| `robot.glb` | A 1.27 m robot with its skeleton, a 16:9 screen for a face and two looping animations. |
| `player.lua` | The local player's script: walking, turning, looking and the first-person camera (engine Lua; see the header of the file for the events it exchanges with the host). |
| `daylight.lua` | The daylight cycle's script: a sun and a moon crossing the sky, and the sky, ambient light and exposure following them (24 minutes of UTC wall-clock time per day; see the header of the file). |
| `generate_assets.py` | Builds both files (Blender script). |
| `render_previews.py` | Imports the two files back into Blender and renders preview images. |

## Conventions a host relies on

- **Axes and units:** glTF's own conventions: metres, +Y up, and the robot faces +Z. The ground is a gently rolling mesh (about -1.3 to 1.7 m, slopes under 8°) with a flat clearing of height 0 around the spawn.
- **`Screen` material:** the robot's face is the mesh primitive whose material is `Screen`. It has a single quad with UVs from 0 to 1, with
  u running left to right as seen by someone in front of the robot, so a camera image appears unmirrored to them. Its base color texture
  is a placeholder face, and the host replaces it with the person's video or avatar picture. The screen is 0.40 × 0.225 m (16:9); other
  aspect ratios need letterboxing.
- **Eye height:** the centre of the screen is at 1.06 m, so a first-person camera goes at about that height.
- **`Spawn` node:** an empty node at the centre of the clearing, where people appear. No trees stand within 14 m of it.
- **Skeleton:** `root`, `hips`, `torso`, `head`, `arm.L`, `arm.R`, `leg.L`, `leg.R`. Every vertex is bound to exactly one joint with weight 1.
- **Animations:** `Walk` (1 s, one step per leg) and `Idle` (2 s), both looping, with linear keys. Each step covers about 0.4 m, so
  `Walk` at normal speed matches about 0.8 m/s; play it faster or slower to match the actual speed.
- **Trees:** three meshes (`TreePine`, `TreeRound`, `TreeBirch`), each placed many times by nodes (glTF instancing).
- **Collision:** the node-name convention (Blender's, read by the engine's importer). `Ground-col` is the drawn ground (a generated terrain mesh) and also a static collider; the player finds its height with a raycast.
  Each tree has a child node named `<Tree>Trunk-colonly`, a collision-only cylinder (8 sides, no material) over its trunk: radius 0.16 m and
  height 1.3 m for `TreePine`, 0.2 m and 2.0 m for `TreeRound`, 0.11 m and 3.2 m for `TreeBirch`, scaled with the tree. The foliage is not solid.
- **Daylight:** the field carries the four nodes `daylight.lua` moves: the directional lights `SunLight` and `MoonLight` (it sets their direction, color
  and intensity every frame) and the discs `Sun` (radius 5 m) and `Moon` (4 m), spheres with `KHR_materials_unlit` that it places 150 m from the camera.

Everything stays inside what the engine's glTF importer supports: no vertex colors or morph targets, and no extensions but `KHR_lights_punctual` (the two lights) and `KHR_materials_unlit` (the two discs; the collision marks are node names), scalar metallic and roughness
values, base color textures only (PNG), single-sided materials, at most one joint per vertex. Both files import with
`asset_mint import-gltf` with no warnings: 10 resources for the robot and 14 for the field (16 with `--emit-level`, which adds the level and
the four collision meshes, and stops drawing the `-colonly` meshes).

## Regenerating

With Blender 5.x, from the repository root:

```bash
blender -b --factory-startup --python assets/worlds/generate_assets.py
```

Add `-- field` or `-- robot` to rebuild only one of them. The output is the same from run to run: the script canonicalizes vertex and face
order, because Blender's bevel otherwise orders new geometry by memory address.

To check the result, render previews into any folder (Cycles on the CPU, a minute or two):

```bash
blender -b --factory-startup --python assets/worlds/render_previews.py -- /path/to/previews
```

To check it against the engine's importer, from the engine's build directory:

```bash
tools/asset_mint/asset_mint import-gltf /path/to/robot.glb --out=/path/to/output --loop=Walk --loop=Idle
```
